# Requirements coverage

Every requirement gathered from the client interview (Ahmed, perfume business
owner), and where it is met. The user stories behind each feature are mapped
to code in [`FEATURE_OWNERSHIP.md`](FEATURE_OWNERSHIP.md).

## Functional

| Requirement                                                                  | How it is met                                                                    |
| ---------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| Browse perfumes                                                              | `/products`: 24 fragrances, paginated                                            |
| Search                                                                       | Search box on the listing and in the header; matches name, notes and description |
| Filter by category and occasion (birthday, wedding, gift, personal use)      | Filter panel; state lives in the URL                                             |
| Filter by price range                                                        | Price slider in the filter panel                                                 |
| Filter by scent family (floral, woody, oriental, fresh)                      | Filter panel                                                                     |
| Sort by price, ascending and descending                                      | Sort control (also by name)                                                      |
| Product details: name, price, size, availability, image, description, notes  | `/products/[id]`: gallery, per-size price, stock label, scent pyramid            |
| Variants: bottle size and gift wrapping only                                 | Size picker + gift-wrapping switch; no other variants                            |
| Cart: add, remove, change quantity, subtotal, total                          | `/cart`                                                                          |
| Checkout: name, phone, address, optional note                                | `/checkout`; email is optional                                                   |
| Review the order summary before sending                                      | Summary panel beside the checkout form                                           |
| Redirect to WhatsApp with products, quantities, prices, total, customer info | The invoice message opens in WhatsApp on _Place order_                           |
| No account needed to order                                                   | Guest checkout; signing in is optional                                           |
| Payment, confirmation and delivery handled manually on WhatsApp              | No payment gateway; the owner moves the order status by hand in the dashboard    |
| FAQs                                                                         | `/faq`                                                                           |
| Reviews and ratings                                                          | Average rating and reviews on every product page                                 |
| Contact: WhatsApp, phone, email, contact form                                | `/contact`                                                                       |
| Wishlist: add and remove                                                     | Heart on every product; `/wishlist`                                              |
| Owner: add, edit, remove products; update prices and details                 | Sanity dashboard → Products                                                      |
| Owner: mark available / out of stock                                         | Product availability, or a single bottle size                                    |
| Owner: view and manage inquiries                                             | Dashboard → New inquiries (New → Replied → Closed)                               |

## Non-functional

| Requirement                                               | How it is met                                                                                                                                                                                                                                                                                                                                                                       |
| --------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Home, listing and product pages load in 2–3 s on Fast 3G  | Listing and product pages are rendered on the server with their data (TanStack Query prefetch + hydration); the first-row photos load eagerly, the rest lazily. Measured on a production build with Chrome's Fast 3G profile, the largest contentful paint was about 1.5 s on the home page and the listing and 2.2 s on a product page. Re-check on the live site with Lighthouse. |
| Images optimized and lazy loaded                          | `next/image` serves AVIF/WebP at the right size; below-the-fold images use `loading="lazy"`                                                                                                                                                                                                                                                                                         |
| HTTPS everywhere                                          | Vercel serves HTTPS only; `Strict-Transport-Security` is set in `next.config.ts`; the site talks to Sanity over HTTPS                                                                                                                                                                                                                                                               |
| 99.9% availability                                        | Hosted on managed platforms (Vercel for the site, Sanity for data and the dashboard); no server of our own to keep up                                                                                                                                                                                                                                                               |
| Responsive: mobile, tablet, desktop                       | Checked at 320–1440 px with no horizontal scroll                                                                                                                                                                                                                                                                                                                                    |
| Keyboard accessible                                       | Every control is a real button, link or input; menus close on Escape and return focus; visible focus rings                                                                                                                                                                                                                                                                          |
| Alternative text                                          | Every product and page image has descriptive `alt` text                                                                                                                                                                                                                                                                                                                             |
| Common accessibility practice                             | Labelled form fields with linked errors, `aria-pressed` / `aria-live` where state changes, colour never the only signal, reduced motion respected                                                                                                                                                                                                                                   |
| Backup and recovery                                       | `pnpm backup` / `pnpm restore` in `dashboard/` (full dataset export and import), per-document revision history in Sanity, one-click rollback of any deployment on Vercel, and the code in Git                                                                                                                                                                                       |
| WhatsApp works on mobile (app) and desktop (WhatsApp Web) | `wa.me` universal links, opened inside the click so browsers do not block them                                                                                                                                                                                                                                                                                                      |
| No online payment data                                    | No card fields anywhere; payment is only a choice of method, settled on WhatsApp                                                                                                                                                                                                                                                                                                    |
